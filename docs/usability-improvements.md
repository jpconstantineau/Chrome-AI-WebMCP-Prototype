Remembered permissions are read from saved preferences at callback entry and rechecked before an operation using a remembered grant. The localStorage preference mirror alone cannot authorize a tool. Broadcast revocation cancels active work in other loaded tabs; direct saved-state revocation is also checked. Ordinary host scope, stale-write fences, permission decisions and deletion confirmation remain independent of any question answer.

Question waits pause active-work time. Native batches cannot combine a question and a write: a question must wait for the human before another proposal. A question before a known native action does not fulfill the action, alter its frozen target/field/value choices, or authorize another operation. Negative answers stop that action. There are at most three question tools in a run, within the normal inference/dispatch budgets. Native proposals can ask before a remaining declared action; the bridge retains direct argument inference for recognized actions and supports questions in explicit or conversational question turns. A question-only turn closes with a tool-free model response; successful writes do not discover new questions after the request is fulfilled.

## Setup sources

The current [Chrome Prompt API guide](https://developer.chrome.com/docs/ai/prompt-api) describes availability, model download and supported desktop hardware. The [Chrome WebMCP guide](https://developer.chrome.com/docs/ai/webmcp#get-started) documents chrome://flags/#enable-webmcp-testing for local development; its extension example separately uses chrome://flags/#prompt-api-tool-use. The prototype's default JSON bridge does not require native tool-call generation. Flag names vary across Chrome builds, and an absent API is not proof that a particular flag is disabled. See the existing [flag research](research/chrome-prompt-api-tool-use.md).
