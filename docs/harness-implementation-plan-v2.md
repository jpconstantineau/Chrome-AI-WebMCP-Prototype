# Harness implementation plan v2

Prepared **2026-10-12** for [harness design v2](harness-design-v2.md), following [next actions](../nextactions.md). This is the execution plan for the selected cycle; acceptance evidence is still to be produced.
One implementation agent owns application code, fixtures, focused tests, and implementation/evidence documentation. The coordinating agent owns README/navigation polish, final runtime checks, independent review coordination, and commit/push.
Preserve the locally modified root [DESIGN.md](../DESIGN.md). Follow [AGENTS.md](../AGENTS.md) and [INTENT.md](../INTENT.md): relative ES modules, static browser execution, no build, dependency installation, backend, external model, or platform polyfill.

## 1. Establish the baseline and implement diagnostic facts first

1. Read the agreed design, current `app.js`, `harness.js`, `workspace.js`, `storage.js`, `service-worker.js`, and relevant runners. Preserve the five workflow planners, eleven review steps, native startup gate, and transaction checks.
2. Add a small diagnostic record with dated pass/fail/unsupported/unknown layers: secure context; required methods; text/English availability; text creation; IndexedDB; registration/discovery; native options/creation/call/feedback. Store errors with name, message, and stage.
3. Prepare a text-only base session from the existing Continue/download gesture. Remove automatic native-tool selection from `createSession()` and startup; constrained JSON is the default even when typed constructors exist.
4. Show Ready only after all required layers pass and all **16 own-page tools** are discoverable. Native-tool creation is an optional diagnostic layer and cannot block usable bridge preparation.
5. Feature-detect typed native interfaces and context methods/events. Missing usage/build/model details are unknown. Provide optional manually entered channel/build/flag/model notes without guessing runtime flags or weights.
6. Normalize only finite valid download progress; absent/invalid progress is indeterminate. At reported 100%, show preparation until `create()` resolves. Cancel/retry and late-created session destruction stay generation-safe.
Exit check: bridge startup with typed constructors, missing-interface blocks, registration failure, 100%-before-create, cancellation, and late session creation have explicit diagnostic outcomes.

## 2. Introduce the host lifecycle and resource ledger

7. Add `agent-host.js` with JSDoc discriminated Run/Round/Call/Child/Event contracts, runtime validators, a pure reducer, and a small coordinator; do not introduce a generic SDK, hook framework, or extract the whole DOM application.
8. Suggested interface: `createHost(policy, clock)`, `startRun(intent)`, `beginRound(run)`, `infer(run, stage, operation)`, `admitBatch(run, proposals)`, `beginDispatch(run, call)`, `settleCall(handle, outcome)`, `commitEffect(handle, receipt)`, `pauseRun(run)`, `continueRun(run)`, `stopRun(run)`, and `admitChild(run, request)`.
9. Host-created opaque run/round/call/child IDs are local bookkeeping. Native `callId`/`callID` is transport correlation only; write signatures are separate. Never expose host/storage IDs through model projections or accept model identity/authority fields.
10. Implement the design state transitions, terminal reasons, and independent effect certainty. Validate identity and monotonic event ordering; every admitted call settles once. Ignore stale inference/UI/report completions.
11. Set configurable defaults: **24 inference stages, 18 dispatch attempts, 180 seconds active work, six dispatches per segment**, one active inference, serial effects/approval, prepared base plus one worker, one child per run, no nesting.
12. Count route, arguments, respond, native proposal/feedback, failed stages, and fallback against the same inference ledger. Count dispatch immediately before invocation; unsuccessful attempts count. Record per-stage latency and aggregate active duration.
13. Use a monotonic active-time accumulator/deadline; pause it around permission cards and Save/Discard/Cancel draft decisions, then resume remaining time. Stop still cancels these waits. Child/canary deadlines use active time too.
14. Continue references the original Run rather than constructing new counters. Reset only segment dispatch count; retain original intent, aliases, outcomes, receipts, signatures, review boundary, total budgets, and authorization. Hide Continue when no total budget remains.
15. Own worker creation/destruction in `try/finally`, including late creation after abort. Replace/release an idle root worker before child creation; never exceed two live sessions or allow overlapping inference.
16. Keep a latest-500-event in-memory journal with active-run outcomes/receipts retained separately. Expose an explicit diagnostic JSON download; no automatic export/upload, database journal, or durable execution queue.
Exit check: fake-clock reducer tests cover admission/order, all totals, wait exclusion, session ownership, cancellation, late events, and continuation without ledger reset.

## 3. Hand off callback commits before rendering

17. Route both adapters through one app coordinator. Replace the counters/flags and transient `workflowReceipts` inside `chat()` with host state while retaining native descriptor discovery, callback validators, and existing execution switch.
18. Implement `invokeOwnTool(descriptor, validatedCall, dispatchHandle)` in `app.js`: establish a private one-use dispatch handoff before `executeTool()`, match its validated name/argument signature at callback entry, and capture the immutable handle before any await. Do not add model-visible identity arguments or treat browser call IDs as authority.
19. Registration calls `executeCallback()` through this local handoff. Unrelated external WebMCP calls use their own callback context and existing permission policy; manual UI writes have no root dispatch handle. Neither attaches receipts to a chat merely because `state.turn` exists. Reject inconsistent/colliding handoffs rather than assigning a commit to an unproven invocation.
20. Extend `committed(action, signal, onCommitted)` or an equivalent private helper. Immediately after `await mutate(...)`, synchronously call `host.commitEffect(capturedHandle, receipt)` **before** memory updates, BroadcastChannel, status, refresh, navigation, model feedback, or generation/abort checks.
21. Immediately after `await transitionReview(...)`, use the same handoff before assigning/rendering `state.review` or navigating. Cover generic create/update/attribute/parent/delete, atomic workflows, and review transitions; distinguish no-change/clarification from an actual committed write.
22. The captured dispatch handle remains receipt-capable after Stop invalidates active generation. Allow only this admitted effect evidence through the late-event gate; it cannot revive dispatch, settle twice, or change the cancelled terminal reason.
23. Derive final saved summaries from these receipts. A committed result survives rendering exceptions, lost WebMCP response, reply inference failure, and Stop immediately after transaction completion. Deletion receipts retain titles/count needed for factual summaries.
24. Return exactly one `{ok:true,data}` or `{ok:false,error:{code,message}}` envelope. Parse a transport string once and validate shape; never recursively unwrap arbitrary nested JSON. Preserve full arguments/results in activity and project bounded facts separately.
25. After a lost dispatched-write response or callback rendering failure, a matching local receipt overrides uncertain transport reporting and proves the committed effect; otherwise settle uncertain and require inspection/new human instruction. Never replay or change proposal transport after this boundary.
26. Preserve immutable approved plans, transaction target/parent/subtree revalidation, delete confirmation, separate complete/skip approval, root chat-grant revocation, and stop-on-first denial/error/clarification. Item success closes review controls for the request; review transition ends dispatch.
Exit check: add callback-level tests that Stop/render failure occur between transaction resolution and outer response handling; assert receipt retention, factual partial success, no replay, and no later dispatch.

## 4. Normalize proposals, correlation, and native opt-in

27. Keep proposal parsing/adapters in `harness.js`; adapters request inference through the host and never execute tools. Normalize to one finalized batch contract containing message and validated calls with separate transport correlation.
28. Validate the entire native batch before the first dispatch: 32-part bound, arguments, IDs, duplicate IDs, both spellings present/ambiguous correlation, and allowed catalog. Retain the observed solitary empty-ID compatibility and identify it in diagnostics.
29. After any terminal sibling, settle every remaining call as skipped with original name/ID. Feedback may use one remaining inference stage but is non-executing; log feedback withheld by cancellation separately. Budget exhaustion cannot leave admitted siblings unaccounted for.
30. Add Tools actions **Test native tool calls**, **Use native proposals** after a successful canary, and **Use JSON proposals**. Accept transport/profile changes only idle, destroy obsolete workers, and invalidate readiness on reload/configuration/native contract failure.
31. Canary is a separate user-gesture diagnostic run: full native options availability, one-tool session creation, exactly one finalized `list_attributes({})`, own-page invocation, exact correlated success/error feedback, then final text. Reject every other call or additional call without execution.
32. Enforce canary three inference stages, one read dispatch, 30 seconds active time. Its callback authorization is an explicit scoped **Allow once** decision even when `state.grant` is true; offer no chat grant and never set/reuse root authority. No mutation, review transition, or navigation occurs.
33. Disabled probe means typed native interfaces unsupported; ordinary bridge remains usable. Constructors/availability/no-tool prose cannot pass the canary. Record options/schema profile, ID spelling, layer outcomes, error stage, and date.
34. Native worker-creation failure selects bridge before proposals. Only a fresh first native inference failure permits one bridge fallback with no finalized/pending calls, dispatch, Continue, cancellation, or uncertainty. Charge both paths to one ledger; later failures settle.
Exit check: native creation versus first inference fallback, after-dispatch failures, full-batch rejection, exact skipped correlation, explicit canary approval despite existing grant, and unsupported/no-tool canary outcomes.

## 5. Project deterministic context and focused catalogs

35. Add `agent-context.js` pure helpers: `closedTurns(history)`, `projectStage(stage, facts)`, `projectResult(result, aliases)`, `catalogProfile(name)`, `fitContext(projection, measurement)`, and specialist snapshot/report helpers. Both adapters consume identical authoritative facts.
36. Keep current exact request, named titles/negation, unresolved question, review boundary, and current-run verified receipts protected outside history allowance. Select complete closed human/assistant turns; remove whole oldest turns and exclude the open request from historical DATA.
37. Supply route descriptions only for routing, selected schema for arguments, and verified results for replies/native feedback. Session memory is disposable: do not append the full transcript repeatedly or clone parent conversation into the specialist.
38. Standard catalog is **12 tools**: five semantic workflows, `weekly_review`, `list_items`, `read_item`, `show_view`, `create_item`, `update_item`, `delete_item`. Keep all **16 public tools** registered/inspectable.
39. Add an idle-only **Standard / Full catalog** diagnostic selector; Full includes `list_attributes`, `read_attribute`, `update_attribute`, `set_parent` for explicit comparisons/primitive contract fixtures with identical gates.
40. Freeze `modelCatalog()` readable alias mappings for the whole run/Continue. Refresh authoritative records and executable descriptors without rebuilding aliases; new records become choices on a fresh human request. Keep referenced tasks outside selected view and clarify duplicate titles.
41. Separate strong public schema, readable model schema, and named default Chromium compatibility decoder projection. Keep a tested description-retaining profile; preserve the literal data field `description`, exact enums, omitted-field meanings, exclusivity, and callback validators.
42. Export shared `inInbox(item)` from `workspace.js`; use it for tree/list and specialist. Add optional `list_items.scope` enum `inbox`; retain `parentId:null` as generic root-record filter and document conjunctive scoped filters. Return applied scope/filters, total, and truncation metadata.
43. Measure actual stage input/options with `measureContextUsage` where available, capture session `contextUsage/contextWindow`, and reserve at least 25% for output/results/schema overhead. Treat missing/unusable measurements as unknown and retain bounded serialized fallback.
44. Trim oldest complete history then optional descriptive facts when measured/bounded input is too large. Never trim exact identities/current request; protected overflow requests narrowing before dispatch. Record `contextoverflow`, dispose session, and rebuild only at a closed boundary without tool replay.
45. Retain 8,000-character result projection ceiling with explicit truncation metadata and current reply grammar initially. Make no-tool completion guarding conservative: verified effects alone produce saved activity; replace suspicious unverified completion claims with factual no-change text and classify the task attempt as failed/unfulfilled.
Exit check: whole-turn boundaries, titles/negation, duplicate names, private-ID exclusion, stable aliases after writes/Continue, literal `description`, scoped Inbox agreement, unknown usage, protected overflow, and injection-as-DATA.

## 6. Add the requested next-action reviewer

46. Add **Ask reviewer** using existing controls: present actionable Inbox or selected Project with its Tasks, then submit a visible human reviewer instruction. Explicit chat requests may admit only when reviewer intent/scope are unambiguous; ordinary guidance/model proposals never admit a child.
47. Host creates one child identity/lineage and frozen scope/revision snapshot, bounded to 40 records/16,000 serialized characters with omissions reported. Project scope includes its Project and Tasks; all references are readable closed choices, and host scope identity stays private.
48. Create a fresh text-only session, with no tools, dispatcher, root grant, review/navigation/approval capabilities, transcript clone, arbitrary code/network, or child spawning. Charge preparation active time and the **one inference** to root limits; child has a 30-second active deadline and no retry.
49. Request exactly `{observations:[{references:[enum],text}],suggestions:[{references:[enum],text}],questions:[text],limitations:[text]}`. Reject actor/identity/extra fields; bound arrays to ten, text to 400 characters, report to 6,000 characters, and references to admitted snapshot.
50. Before accepting, reread current scope membership and record revision signature; validate lineage, shape, references, cancellation, and freshness. Stale/malformed/late/timeout/budget failure settles honestly with zero dispatch or effect.
51. Host attaches identity/revision and renders **Reviewer suggestions; no changes made** with evidence labels using text nodes. Advice cannot grant root permission or authorize writes; any suggested change requires a new human root instruction and factual permission outcome.
52. Parent Stop destroys child work, rejects late reports, and preserves parent receipts. Reload discards child/continuation/approval/native readiness; existing domain/history/preferences and paused review survive without resuming execution.
Exit check: explicit admission only, one child/session inference, zero page calls, grant isolation, useful typed references, bounded omissions, changed membership/revision, injection, timeout, Stop, and total-budget failure.
